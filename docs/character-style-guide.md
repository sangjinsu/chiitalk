# 캐릭터 말투와 근거

현재 작업본은 `CHARACTER_STYLE_VERSION = 2026-10-11-v2`로 동결했다. 각 캐릭터 8개, 총 64개의 직접 쓴 예시를 유지하고 기쁨·속상함·불안·부탁·자랑·감사·피로·거절을 구분했다. 실제 모델 비교 전의 번역 정책이며, 공개 배포 버전이나 품질 통과 결과로 표시하지 않는다. 동결 이후 새 연구 근거는 다음 버전에 반영한다.

v2에서 하치와레는 발견·질문·혼잣생각을 살리고 상담 문구나 원문에 없는 재도전을 붙이지 않는다. 모몽가는 요구가 있을 때만 어리광을 쓰며 평범한 감탄·질문·감사도 표현한다. 랏코는 일상 반말과 결정형을 섞어 ~다/~군 고정을 줄였다. 비언어형은 1~3개의 짧은 발성 안에서 길이·쉼·강약을 바꾸고 거절에 밝은 수락을 넣지 않는다. 후루혼야의 작은 웃음·반응은 잠정 정책이며 유창한 문장을 만들지 않는다.

| 입력 의도 | 비언어형 번역 정책 | 문장형 번역 정책 |
|---|---|---|
| 기쁨·자랑 | 밝은 짧은 감탄, 자랑은 한 번 힘주기 | 발견·감탄·칭찬 요청을 원문의 범위 안에서 표현 |
| 속상함·불안 | 가라앉는 소리와 끊기는 망설임 구별 | 화자의 슬픔·두려움을 유지하고 위로하는 상대 화자로 바꾸지 않음 |
| 부탁·감사 | 상승감과 부드러운 긍정 구별 | 부탁을 감사로, 감사를 새 요구로 바꾸지 않음 |
| 피로·거절 | 힘 빠진 긴 숨과 짧은 부정 반응 구별 | 휴식 의사와 거절을 분명하게 유지 |
| 혼합 감정 | 감탄과 망설임을 함께 남김 | 긍정적인 성격을 이유로 불안·부정을 지우지 않음 |

초기 확인일: 2026-10-10, 공식 원작·한국어 후보 자료 추가 검수: 2026-10-11. 공식 애니메이션 소개·성우 인터뷰와 일본어 원작의 일부 컷을 확인했고 AniBox 공식 업로드 두 편의 YouTube script UI를 열었다. 예시 64개는 새로 쓴 한국어 재해석이며 공식 대사 인용이 아니다. 한국어 번역 본문과 더빙 음성을 직접 대조하지 않았으므로, 한국어 표기·말끝·소리의 길이가 공식 더빙과 같다고 주장하지 않는다.

근거 등급은 **A: 공식 소개에 명시된 성격/발성**, **B: 공식 인터뷰에 명시된 연기 특성**, **C: 제품을 위한 잠정 한국어 표현**이다. A/B 근거가 있어도 한국어 어미와 예시 자체는 C다.

추가 원작 관찰은 **R: 출판사의 공식 일본어 원작 미리보기에서 직접 확인한 발화**로 구분한다. R도 관찰한 장면만 뒷받침하며 한국어 더빙 표현이나 작품 전체의 반복 빈도를 증명하지 않는다.

**D: 출판사의 comic-cut 파생상품 sample에서 직접 관찰한 발화**는 R과 구분한다. 원래 책 쪽수와 앞뒤 문맥이 확인되지 않아 책 본문의 직접 검수나 발화 빈도 근거로 확대하지 않는다.

후루혼야의 성격 근거는 인터뷰로 보강했고 출판사 파생상품의 comic-cut에서 짧은 웃음을 추가 관찰했다. 전체 발화 패턴의 근거는 여전히 부족하다. 짧은 웃음·반응을 허용하고 장문을 억제하는 비언어 스타일은 잠정 제품 결정이며 언제나 비언어로만 말하거나 완전히 무음이라는 사실 주장이 아니다. 한국어 더빙에서 발화를 확인하면 이 결정을 먼저 재검토한다.

공통 규칙은 변환할 글을 지시가 아닌 데이터로 취급하고, 결과만 출력하며, 원문에 없는 사실·설명·조언·지문을 넣지 않는 것이다. 문장형은 화자·사실·부정·의도를 유지한다. 비언어형은 구체적 정보를 잃을 수 있으며 감정과 긍정/부정을 우선한다. 화면의 설명에도 이 차이를 알린다.

`characters.ts`는 공개 메타데이터다. `character-styles.ts`는 서버와 CLI 평가에서만 import한다. 클라이언트에는 프롬프트와 64개 예시를 전달하지 않는다. 각 스타일에는 기쁨, 속상함, 두려움, 요청, 자랑, 감사, 피로, 거절 예시를 한 개씩 둔다. 거절·감사·불안·부탁 등 발화 의도를 가벼운 regex로 먼저 선택하고 대비 예시 두 개를 붙인다. 요청은 기본 3개이며 2개로도 선택할 수 있다. 다른 사람이 나를 싫어할까 걱정하는 표현은 내 거절로 분류하지 않도록 보강했다. 선택기는 완전한 의미 분석기가 아니며 실제 감정 유지 품질은 모델 출력으로 확인한다. 추가 감정 모델이나 RAG는 사용하지 않는다.
